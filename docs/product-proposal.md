# VeilDrop — Product Proposal

**Idea (from the provided list):** *Anonymous Feedback / Survey — verifiable participation, private responses.*

**Status:** submitted for approval — Midnight Academy Level 3.

## The problem

Organizations — companies, universities, newsrooms, DAOs — need honest feedback, but
whistleblowers and survey respondents routinely stay silent because speaking up exposes
them. Today's "anonymous" forms are either not anonymous at all (IP logs, reply-to
addresses) or trust the platform to store secrets it can be compelled to reveal.

## The product

VeilDrop is an anonymous feedback/reporting DApp on Midnight. A reporter submits a
**one-way commitment** of their report (SHA-256 of title + description + category +
random salt) to the public ledger, together with a category and a domain-separated
pseudonym. Investigators update the report's public status. The reporter can later
prove they authored a given report by re-deriving the commitment.

The ledger proves participation ("a report about X was filed, and it is now
under investigation") without proving the substance ("here is the report's text, and
here is who wrote it").

## What an observer can and cannot learn

| An observer CAN learn | An observer CANNOT learn |
| --- | --- |
| That a report exists, its category, its public status | The report title or description |
| The reporter's pseudonym (domain-separated from their secret key) | The reporter's identity or secret key |
| The authorized-credential commitment | The credential itself (`proveAuthorization` is a zkSNARK) |

## How Midnight's privacy model makes it work

- **Public ledger state**: `ReportEntry` — commitment, category, status, timestamp,
  pseudonym — is stored in `Ledger` in `contract/src/main.compact`.
- **Private witnesses**: `reporterSecret` and `credentialSecret` in
  `contract/src/witnesses.ts` never appear on-chain.
- **`disclose()`**: the contract deliberately discloses only what is needed (commitment,
  category, status, pseudonym); everything else stays inside the zk-SNARKs generated by
  `submitReport` and `proveAuthorization`.
